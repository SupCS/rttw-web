# wealthy — личный учёт

Онлайн-приложение с входом и PostgreSQL. Совместный учёт удалён; бюджеты и цели — следующий этап.

## Готово

- Личные мультивалютные счета, начальные остатки, удаление с исключением остатка или атомарным переносом валют/долгов; история сохраняется, будущие платежи отменяются.
- Категории/подкатегории, SVG-иконки, цвета, объединение; операции и splits, переводы/комиссии, поиск, редактирование, копирование, отмена удаления.
- Аналитика за день/неделю/месяц/год/диапазон; отдельные валюты либо явный пересчёт; bigint, исходные суммы/даты/FX-снимки; будущие записи и переводы исключены из фактических доходов/расходов.
- Независимые повторяющиеся платежи: предпросмотр дат, пауза/возобновление, остановка, защита от дублей.
- Cookies-вход, личный учёт по аутентифицированному пользователю; JSON export/preview/restore версии 2. Старый формат версии 1 отклоняется.
- Midnight, 12 тем, en/uk/ru, SVG-флаги (ru — пиратский), адаптивность; по одной кнопке создания счёта, отдельные страницы настроек.

## Запуск и размещение

Node.js 22.13+. `npm install`, затем `npm run api:local`; отдельно `npm run dev`. Сайт: http://127.0.0.1:5173; локальная база: `.local-data`.

Railway размещён отдельно. Dockerfile из корня; DATABASE_URL, HTTPS WEB_ORIGIN. Pre-Deploy: `npm run db:migrate --workspace @rttw/api`; Healthcheck: `/ready`. Старое приложение не менять.

**Согласованная очистка:** миграция `1792300000000_personal-only-reset.sql` удаляет все прежние финансовые данные, участников и приглашения; пользователи, пароли и сессии сохраняются. Выполняется однократно при миграции. Исторические SQL-файлы оставлены только для обновления существующих БД.

Проверка: `npm run check`; целевые сценарии миграции, доступа, финансовых расчётов, удаления, платежей и резервных копий. Полный набор — вручную: `npm run check:full`.

## Архив домохозяйств — для возможного возвращения

Исходники до удаления: Git `42b8bec`, `apps/api/src/households`, `apps/api/test/web-auth.test.ts`.

- Создание: имя после trim 1–120 символов, поддерживаемая валюта. После первоначального автосоздания «My household» добавлялся отдельный личный учёт.
- Членство: уникальная пара домохозяйство/пользователь, роли owner/member, состояния invited/active/left/removed; доступ только активным неудалённым участникам неудалённого домохозяйства. Личный учёт недоступен приглашениям.
- Владелец менял название/валюту, приглашал, восстанавливал копии. Участники читали/изменяли общий журнал. Счета имели personal/shared и владельца-участника; аналитика переключала области.
- Приглашение: нормализованный email, случайный токен (в БД только SHA-256), срок 7 суток, однократное принятие соответствующим вошедшим пользователем; повторное принятие, другой email и неактивный пригласивший отклонялись.
- Критерии: CSRF origin/header, серверная авторизация каждого чтения/изменения/export/restore, запрет смешанных ссылок, блокировки/транзакции, revision-конфликты, долговечные receipts против дублей; restore только в пустой журнал после проверки, предпросмотра и подтверждения.
- Проверялись чужой доступ, роли, cookie-ротация/выход, принятие приглашений, неизменность исторических сумм/FX при смене валюты, атомарность восстановления и изоляция личных данных. При возвращении заново восстановить модель доступа, миграции, переводы и эти сценарии.
